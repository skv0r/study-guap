# ИСПРАВЛЕНИЕ ПРОБЛЕМЫ: Результат записался не туда

## Проблема

После выполнения команды:
- 6A = F7 ✓ (правильно)
- 6B = FB ✗ (должно быть 04, но стало FB - результат!)
- 6C = 1D ✗ (должно быть FB, но стало 1D)

## Диагностика

**СРОЧНО ПРОВЕРЬТЕ:**

1. **Что было в R2 ДО выполнения команды?**
   - Должно быть: R2 = 006C
   - Если было R2 = 006B - вот в чём проблема!

2. **Что стало в R2 ПОСЛЕ выполнения?**
   - Проверьте текущее значение R2

3. **Что стало в R0 и R1?**
   - R0 должно стать 04D3 (было 04CF)
   - R1 должно стать 04D7 (было 04D3)

## Решение 1: Проверка регистров

Если R2 было не 006C, а 006B - исправьте:

```
R2 = 0000006C  (обязательно 006C, не 006B!)
```

Затем:
1. Восстановите X2: адрес 006B = 04
2. Восстановите X3: адрес 006C = 19
3. Запустите команду снова

## Решение 2: Использование прямой адресации

Если проблема в формате адресации `(R2)`, попробуйте использовать прямой адрес.

**ВАРИАНТ А: Прямая адресация слова (если поддерживается)**

```
Адрес 03C0: C0    (ADDB3)
Адрес 03C1: 90    (@(R0)+)
Адрес 03C2: 91    (@(R1)+)
Адрес 03C3: 8F    (прямая адресация слова)
Адрес 03C4: 6C    (младший байт адреса)
Адрес 03C5: 00    (старший байт адреса)
```

**ВАРИАНТ Б: Использование другого регистра**

Попробуйте использовать R3 вместо R2:

```
R3 = 0000006C
```

И команду:
```
Адрес 03C0: C0    (ADDB3)
Адрес 03C1: 90    (@(R0)+)
Адрес 03C2: 91    (@(R1)+)
Адрес 03C3: 53    ((R3) вместо (R2))
```

## Решение 3: Проверка формата команды

Убедитесь, что команда записана правильно:

```
03C0: C0
03C1: 90
03C2: 91
03C3: 52
```

Если в 03C3 записано не 52, а что-то другое - вот проблема!

2. Если R2 = 006B, исправьте на 006C
3. Восстановите данные: 006B = 04, 006C = 19
4. Запустите снова
