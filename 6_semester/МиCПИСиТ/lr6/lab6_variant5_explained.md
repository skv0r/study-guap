## 0) Что нужно знать новичку

### Процедура vs функция

- **Процедура** (`create procedure ...`) — вызывается командой `CALL ...;`, может делать изменения в БД (INSERT/UPDATE/DELETE), может создавать временные таблицы и т.п. Процедура **ничего не “возвращает” как значение** (хотя может писать `NOTICE`, заполнять таблицы и т.д.).
- **Функция** (`create function ... returns ...`) — вызывается в `SELECT`, **возвращает значение** (скаляр) или набор строк (табличная функция). В PostgreSQL функции тоже могут менять данные, но обычно по смыслу их используют для вычислений/выборок.

### Язык `plpgsql`

`plpgsql` — процедурный язык PostgreSQL: переменные, `IF`, `LOOP`, `RAISE`, `SELECT ... INTO`, и т.д.

### Что предполагает скрипт по структуре БД

Скрипт использует таблицы (с русскими именами в кавычках):

- `"Вуз"`, `"Факультет"`, `"Группа"`, `"Студент"`
- `"Конференция"`, `"Программа_конференции"`, `"Выступление"`, `"Выступление_студент"`

Связи по смыслу такие:

- ВУЗ → Факультеты → Группы → Студенты
- Конференция → Программы → Выступления
- `"Выступление_студент"` связывает студентов и выступления (кто в каком выступлении участвовал)

Если у вас названия/поля отличаются — процедуры не скомпилируются.

### Как запускать скрипт

Варианты:

- **psql**:
  - открыть psql нужной базы
  - выполнить файл: `\i lr6/lab6_variant5.sql`

Важно: в скрипте есть примеры вызовов, которые **закомментированы**. Если их раскомментировать — данные будут изменены.

## 1) `pr_add_student_with_group(...)` — вставка студента + автосоздание группы

Файл: `lab6_variant5.sql`, блок “1)”.

### Задача простыми словами

Нужно добавить студента (ФИО) в группу.

- Если группа с парой **(факультет, номер группы)** уже есть — использовать её.
- Если группы ещё нет — **создать** запись в `"Группа"`.
- Если студент с таким же ФИО уже есть в этой группе — **не добавлять дубль**.

### Входные параметры

- `p_fio text` — ФИО студента
- `p_nomer_grupy text` — номер группы (строкой)
- `p_nomer_fakulteta smallint` — номер факультета
- `p_vuz text default 'ГУАП'` — вуз, по умолчанию “ГУАП”

### Ключевые приёмы, которые тут используются

- **Проверка входа**: `if btrim(p_fio) = '' then raise exception ... end if;`
  - `btrim` убирает пробелы по краям.
  - `raise exception` — “жёсткая” ошибка: выполнение останавливается.
- **Поиск значения в переменную**: `select ... into v_id_fakulteta ...`
  - Если строка не найдена — переменная остаётся `NULL`.
- **“Создай, если не существует”**:
  - сначала `select ... into v_id_grupy`
  - если `NULL` → `insert ... returning ... into v_id_grupy;`
- **Проверка на дубликат**: `if exists (select * from "Студент" ... ) then raise notice ...; return; end if;`
  - `raise notice` — мягкое сообщение, не ошибка.
  - `return;` — выйти из процедуры.

### Что в итоге меняется в БД

- Иногда добавляется новая строка в `"Группа"`.
- Затем добавляется строка в `"Студент"`.

## 2) `pr_delete_student_cleanup_group(p_fio)` — удалить студента и “осиротевшую” группу

Файл: блок “2)”.

### Задача

Удалить студента по ФИО. Но сделать это аккуратно:

1) сначала удалить его связи в `"Выступление_студент"`  
2) потом удалить строку из `"Студент"`  
3) если в группе больше не осталось студентов — удалить и строку группы из `"Группа"`

### Почему удаляют `"Выступление_студент"` заранее

Чаще всего в `"Выступление_студент"` стоит внешний ключ на `"Студент"`. Если попытаться удалить студента, пока есть связанные строки, БД может запретить удаление (ошибка FK).

### Важные места для понимания

- `select ... into v_id_student, v_id_grupy ... where s."ФИО" = btrim(p_fio);`
  - ФИО не уникально в реальной жизни — но в учебных БД часто допускают. Здесь если найдётся несколько студентов с одинаковым ФИО — `SELECT INTO` упадёт с ошибкой “more than one row returned”. Учтите это как ограничение решения.
- Если студент не найден → `raise notice` и `return`.
- Затем два `delete`:
  - из `"Выступление_студент"` по `ID_студента`
  - из `"Студент"` по `ID_студента`
- И условное удаление группы, если нет студентов с таким `ID_группы`.

## 3) `pr_delete_group_with_students(...)` — “каскадное” удаление группы вручную

Файл: блок “3)”.

### Задача

Удалить группу (по номеру группы + номеру факультета + вуз). Но при этом удалить всё, что “ниже”:

1) участия студентов этой группы в выступлениях (`"Выступление_студент"`)  
2) студентов этой группы (`"Студент"`)  
3) саму группу (`"Группа"`)

### Почему тут `DELETE ... USING`

Фрагмент вида:

- `delete from "Выступление_студент" vs using "Студент" s where vs."ID_студента" = s."ID_студента" and s."ID_группы" = v_id_grupy;`

Это удобный способ удалять строки из одной таблицы, отфильтровывая их через другую таблицу (как “DELETE с JOIN”).

### Замечание по проектированию

Если в схеме внешние ключи настроены как `ON DELETE CASCADE`, многие такие удаления можно было бы делать одной командой. Но лабораторная как раз тренирует **процедурную логику**, поэтому каскад реализован вручную.

## 4) `fn_avg_participations_per_student(p_vuz)` — среднее число участий на одного студента

Файл: блок “4)”.

### Задача

Посчитать среднее число записей в `"Выступление_студент"` на одного студента в заданном вузе, причём:

- студент с **нулём** участий тоже должен учитываться (иначе среднее будет завышено)

### Как это достигается

- Делается `left join "Выступление_студент" vs ...` — чтобы у студентов без участий `vs` был `NULL`.
- Затем `count(vs."ID_выступления")`:
  - `COUNT(column)` не считает `NULL`, поэтому для студента без выступлений получится `0`.
- Далее берётся `avg(...)` по всем студентам.
- `coalesce` + `round` приводят к числу с 2 знаками после запятой и защищают от `NULL`.

### Почему функция помечена как `stable`

`stable` означает: “в рамках одного запроса результат не меняется”. Для чистых вычислений/чтений это нормально и может помогать оптимизатору.

## 5) `pr_fill_faculty_stats()` — собрать статистику по факультетам во временную таблицу

Файл: блок “5)”.

### Что такое временная таблица

`create temp table ...` создаёт таблицу **только на время текущей сессии** (подключения). Другие пользователи её не видят.

`on commit preserve rows` означает: при `COMMIT` строки не очищаются (то есть таблица и данные живут до конца сессии).

### Что делает процедура

1) удаляет предыдущую временную таблицу `tmp_faculty_stats`, если она есть  
2) создаёт `tmp_faculty_stats` с колонками:
   - номер факультета, название
   - количество групп
   - количество студентов
   - количество “участий” (строк в `"Выступление_студент"`)
   - средняя длина темы выступления (по `char_length("Название_темы")`)
3) вставляет данные по факультетам вуза “ГУАП”

### Почему тут много вложенных `select`

Это способ посчитать несколько независимых метрик “по факультету”:

- количество групп: `count(*) from "Группа" where ...`
- количество студентов: `count(*) from "Студент" join "Группа" ...`
- количество участий: `count(*) from "Выступление_студент" join ...`
- средняя длина темы: `avg(char_length(...)) join ...`

Такой стиль проще читать новичку, чем один огромный запрос с кучей `GROUP BY`, хотя по производительности на больших данных может быть хуже.

## 6) `pr_demo_conference_participation_loop(p_vuz)` — цикл по конференциям + отчёт во временную таблицу

Файл: блок “6)”.

### Задача

Сделать “отчёт”: для каждой конференции посчитать, сколько раз студенты заданного вуза участвовали в выступлениях на этой конференции.

### Как это сделано

1) создаётся временная таблица `tmp_conf_loop(konferenciya, uchastiy)`
2) цикл:

- `for r in select k."Название" as nazvanie from "Конференция" k order by ... loop ... end loop;`

`r` — это запись (`record`) с полем `nazvanie` (название конференции).

3) внутри цикла:
   - выполняется `select count(*) into v_cnt` по длинной цепочке `join`, которая связывает вуз → студентов → участия → выступления → программы → конференции
   - результат вставляется в `tmp_conf_loop`

### Почему это полезно в лабораторной

Показывает управляющие конструкции PL/pgSQL:

- `FOR ... IN SELECT ... LOOP`
- переменные (`v_cnt`)
- заполнение “отчётной” временной таблицы

## 7) `fn_students_by_conference(p_konferenciya)` — табличная функция “студенты конференции”

Файл: блок “7)”.

### Задача

Вернуть список студентов (ФИО + номер группы), которые выступали на указанной конференции.

### Особенности реализации

- Это **табличная функция**: `returns table (fio ..., nomer_grupy ...)`
- Она написана на чистом SQL (`language sql`), без `plpgsql`.
- Используется `select distinct`, чтобы один и тот же студент не повторялся, если у него несколько выступлений на конференции.

### Как вызывать

Пример в конце скрипта:

- `select * from fn_students_by_conference('Информатика') limit 20;`

## Мини-памятка по отладке и типичным ошибкам

- **“relation does not exist”**: нет таблицы/не та схема/не то имя (в т.ч. из‑за кавычек и регистра).
- **“column does not exist”**: в вашей БД поля названы иначе.
- **“more than one row returned by a subquery used as an expression” / ошибка `SELECT INTO`**: условие поиска возвращает несколько строк (например, ФИО не уникально).
- **Пустые результаты в статистике**: возможно, в данных нет связей по конференциям/выступлениям или вуз называется не ровно так, как ожидается (`'ГУАП'`).
