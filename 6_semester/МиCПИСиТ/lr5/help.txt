Кратко про скрипт лабораторной работы № 5 (для новичка)

Общая идея. В базе есть студенты, группы, факультеты, конференции, выступления и связь «кто в каком выступлении участвовал». Запросы ниже отвечают на вопросы на русском, а SQL переводит это в проверки «существует ли строка, удовлетворяющая условию» (EXISTS) или «не существует» (NOT EXISTS).

ж) Четвёртый факультет и ни одного выступления. Берём студентов ГУАП с номером факультета 4. NOT EXISTS по таблице участия означает: «ни одной строки, где этот студент числится в выступлении». Если подзапрос ничего не находит, условие истинно — студент попадает в ответ.

з) Были на всех конференциях. Внешнее NOT EXISTS по списку конференций читается так: «не найдётся конференции, для которой…». Внутри — ещё один NOT EXISTS: «не найдётся участия этого студента в выступлении именно этой конференции». Два «не» подряд дают смысл «для каждой конференции есть хотя бы одно участие». Студентов без единого выступления запрос не выведет: для любой конференции внутреннее условие ломается.

и) Всегда вместе. Берутся пары разных студентов (второй с большим ID, чтобы не дублировать пары). EXISTS в начале отсекает тех, у кого вообще нет участий. Два симметричных NOT EXISTS проверяют: у каждого выступления первого есть второй в том же выступлении и наоборот. Если множества выступлений совпадают, пара попадает в результат.

Временная таблица и INSERT / UPDATE / DELETE. Создаётся temp-таблица со столбцами студент, ФИО, число участий. INSERT заполняет её теми, у кого участий меньше среднего по всем (подзапросы считают среднее по уже посчитанным группам). UPDATE дописывает пометку к ФИО у тех, чей факультет «без Информатики» — отбор через IN и вложенный NOT EXISTS по факультетам. DELETE убирает строки у студентов, у которых NOT EXISTS участия на «Робототехника и ИИ». Потом SELECT показывает таблицу, DROP её убирает.

Пересечение ФИО (как в прошлой лабе, но через EXISTS). Два подзапроса в WITH задают множество A (Информатика) и B (Робототехника и ИИ). Основной SELECT оставляет строки A, для которых EXISTS находит такое же ФИО в B — это пересечение множеств без ключевого слова INTERSECT.

Блок с NULL. Таблицы A и B заданы буквально двумя значениями: NULL и строка. INTERSECT считает NULL обычным значением, поэтому NULL может войти в пересечение, если он есть в обоих множествах. EXISTS сравнивает строки через «=»; в SQL сравнение NULL = NULL не даёт «истину», поэтому строка с NULL из A не «пересекается» с NULL из B через EXISTS. EXCEPT и NOT EXISTS при наличии NULL дают не тот же результат, что чистое сравнение строк в INTERSECT — на этом учебном примере это видно по последним четырём запросам.
