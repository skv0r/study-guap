Лабораторная работа №5
Тема: Ограничение входных данных и приведение их к требуемому формату в системе управления оборудованием
Вариант 1: Умный дом

Цель работы
Целью лабораторной работы является получение практических навыков валидации входных параметров на стороне сервера, приведения данных к корректному формату и отклонения некорректных управляющих команд без изменения состояния устройств.

Задание
В соответствии с методическими указаниями для лабораторной работы №5 требуется модифицировать функции управления вещами так, чтобы все входящие значения проверялись перед применением. Необходимо использовать как минимум два формата входных данных, включая строковый формат, и применить хотя бы одно регулярное выражение.

Ход работы
В ходе выполнения лабораторной работы сохранена архитектура лабораторной работы №4: мониторинг выполняется через маршруты `GET /connect/temperature`, `GET /connect/light`, `GET /connect/lock`, а управление — через `GET /command/temperature`, `GET /command/light`, `GET /command/lock`. Отличие ЛР5 заключается в том, что перед вызовом `applyCommand` для каждой вещи добавлена серверная проверка входных значений. На рисунке 1 изображена страница приложения с результатами успешных и отклонённых команд.
Рисунок 1 - Скриншот браузера: видны блоки управления и сообщения об ошибках валидации (вставить снимок).

Для температуры реализована проверка строкового значения регулярным выражением (допускаются форматы с точкой и запятой), затем выполняется преобразование к числу с контролем `NaN`. Для света проверяются два параметра: логическое состояние (`enabled`) по словарю допустимых строк и яркость (`brightness`) как целое число в диапазоне 0-100. Для замка параметр `locked` проверяется по набору допустимых строковых представлений состояния. При некорректных данных сервер возвращает код 400 и JSON с полем `error`, а состояние устройств не изменяется. На рисунке 2 изображена вкладка «Сеть» с примерами отклонённых запросов.
Рисунок 2 - Скриншот Network: видны запросы `/command/...` с кодом 400 и текстом ошибки (вставить снимок).

В консоли сервера логируются обращения к маршрутам и причины отклонения неверных значений, что позволяет наглядно подтвердить работу механизма валидации. На рисунке 3 изображён фрагмент журнала терминала при отправке ошибочных команд.

Вывод
В результате выполнения лабораторной работы реализована серверная валидация входных данных для всех устройств варианта «Умный дом» с использованием регулярных выражений, словарей допустимых значений и проверки диапазонов. Полученная реализация исключает применение некорректных команд и подготавливает систему к дальнейшему развитию в следующих лабораторных работах.
