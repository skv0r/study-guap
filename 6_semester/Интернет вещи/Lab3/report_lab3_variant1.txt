Лабораторная работа №3
Тема: Организация получения и вывода данных с удалённого оборудования
Вариант 1: Умный дом

Цель работы
Целью лабораторной работы является получение практических навыков организации получения данных с удалённого оборудования и вывода этих данных в веб-интерфейсе. В рамках варианта «Умный дом» в качестве оборудования используется программный эмулятор: состояние вещей периодически обновляется на сервере, а клиент запрашивает данные мониторинга по отдельным маршрутам.

Задание
В соответствии с методическими указаниями для лабораторной работы №3 требуется реализовать эмуляторы вещей для всех классов, созданных в предыдущей работе, разработать один или несколько интерфейсов для вывода данных от эмуляторов. В рамках данной работы в интерфейс передаются только данные мониторинга; передача управляющих команд рассматривается в следующей лабораторной работе. Для каждой вещи необходимо реализовать собственный запрос к серверу (в пособии — ajax) и собственную функцию подключения на стороне сервера.

Ход работы
В ходе выполнения лабораторной работы на сервере Node.js с использованием Express организована раздача статических файлов из каталога `public` (страница `index.html` и клиентские сценарии). Для каждой вещи (`TemperatureSensor`, `LightController`, `SmartLock`) создан отдельный маршрут `GET /connect/...`, возвращающий JSON с полями мониторинга после вызова метода `connect()` цифрового двойника. В базовом классе `Thing` реализован общий сценарий `connect()`: вызов `emulate()` и формирование полезной нагрузки через `buildPayload()` в наследниках. На стороне клиента в файлах `script.js` и `index.js` реализованы функции периодического опроса сервера с интервалом одна секунда (`setInterval`), для каждой вещи выполняется отдельный запрос `fetch` к соответствующему маршруту `/connect/temperature`, `/connect/light`, `/connect/lock`, полученный JSON используется для обновления элементов страницы. Вывод
В результате выполнения лабораторной работы была реализована схема получения данных мониторинга с эмулируемого оборудования через отдельные HTTP-маршруты для каждой вещи, организован вывод данных во веб-интерфейсе с периодическим опросом сервера. Использование общего метода `connect()` в абстрактном классе `Thing` и индивидуальных реализаций `emulate()` и `buildPayload()` в наследниках соответствует выбранному варианту проектирования и требованиям методических указаний к лабораторной работе №3. Реализация может быть использована как основа для следующей работы по передаче управляющих команд.
