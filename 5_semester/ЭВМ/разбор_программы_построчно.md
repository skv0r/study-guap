# Построчный разбор программы VAX-11

## Структура программы из рабочего файла

Программа начинается с адреса **A8** (168 в десятичной системе).

---

## КОМАНДА 1: Адрес A8

**Код:** `8E 53 98`  
**Мнемоника:** `MNEGB R3 @(R8)+`  
**Комментарий:** X1 = -X2

### Что делает команда:

MNEGB = Move Negate Byte (переместить отрицание байта)

### Разбор по байтам:

- **8E** = код операции MNEGB (move negate byte)
- **53** = операнд 1: R3 (способ адресации 6 - прямая регистровая)
  - R3 содержит значение X2 = 1C (hex) = 28 (dec)
- **98** = операнд 2: @(R8)+ (способ адресации 9 - косвенная через память с автоувеличением)
  - R8 содержит адрес ПЯ1 = 402
  - @(R8)+ означает:
    1. Взять адрес из R8 (402)
    2. Из ячейки 402 взять адрес операнда (0F - адрес X1)
    3. Записать результат по адресу 0F (X1)
    4. Увеличить R8 на 4 (размер длинного слова) → R8 = 406

### Что происходит:

1. Берется значение из R3 (X2 = 1C)
2. Вычисляется отрицание: -1C = E4 (в дополнительном коде)
3. Результат записывается по адресу X1 (0F)
4. R8 увеличивается до 406

### Результат:

- X1 (адрес 0F) = E4 (hex) = -28 (dec)
- R8 = 406

---

## КОМАНДА 2: Адрес AB

**Код:** `C0 98 69`  
**Мнемоника:** `ADDL2 @(R8) (R9)+`  
**Комментарий:** X8 = X8 + X7

### Что делает команда:

ADDL2 = Add Longword 2 операнда (сложение длинных слов, 2 операнда)

### Разбор по байтам:

- **C0** = код операции ADDL2
- **98** = операнд 1: @(R8)+ (способ адресации 9 - косвенная через память с автоувеличением)
  - R8 = 00000406 (после команды 1)
  - @(R8)+ означает:
    1. Взять адрес из R8 (406)
    2. Из ячейки памяти по адресу 406 прочитать длинное слово = 0000002D
    3. Это адрес X7 (2D)
    4. Взять значение из X7 (00393100)
    5. Увеличить R8 на 4 → R8 = 40A
  - **ВАЖНО:** В мнемонике указано @(R8), но код 98 означает @(R8)+ (с автоувеличением)
- **69** = операнд 2: (R9)+ (способ адресации 7 - косвенная с автоувеличением)
  - R9 содержит адрес X8 = 37
  - (R9)+ означает:
    1. Взять адрес из R9 (37)
    2. Взять значение из X8 (FFE3670F)
    3. Увеличить R9 на 4 → R9 = 3B
  - Результат записывается обратно по адресу X8 (37)

### Что происходит:

1. Берется X7 из памяти по адресу 2D (через ПЯ2)
2. Берется X8 из памяти по адресу 37 (через R9)
3. Выполняется сложение: X7 + X8
4. Результат записывается в X8
5. R9 увеличивается до 3B

### Результат:

- X8 (адрес 37) = X7 + X8 = 00393100 + FFE3670F = 001C980F
- R8 = 0000040A (увеличился на 4)
- R9 = 0000003B (увеличился на 4)

---

## КОМАНДА 3: Адрес AE

**Код:** `A1 70 52 5C`  
**Мнемоника:** `ADDW3 -(R0) R2 RC`  
**Комментарий:** X6 = X5 + X4

### Что делает команда:

ADDW3 = Add Word 3 операнда (сложение слов, 3 операнда)

### Разбор по байтам:

- **A1** = код операции ADDW3
- **70** = операнд 1: -(R0) (способ адресации 8 - косвенная с автоуменьшением)
  - R0 = 00000025 (начальное значение)
  - -(R0) означает:
    1. Уменьшить R0 на 2 (размер слова) → R0 = 23
    2. Взять адрес из R0 (23)
    3. Взять слово из памяти по адресу 23 = F870 (X4)
  - **ПОЧЕМУ R0=25?** Это начальное значение регистра, которое затем уменьшается до 23 для доступа к X4
- **52** = операнд 2: R2 (способ адресации 6 - прямая регистровая)
  - R2 содержит значение X5 = 0559
- **5C** = операнд 3 (результат): RC (R12, способ адресации 6 - прямая регистровая)
  - RC = 00002341 (начальное значение - X6)
  - Результат записывается в RC (заменяя старое значение)

### Что происходит:

1. R0 уменьшается до 23
2. Берется X4 из памяти (F870)
3. Берется X5 из R2 (0559)
4. Выполняется сложение: X4 + X5 = F870 + 0559 = FDC9
5. Результат записывается в RC

### Результат:

- RC = 0000FDC9 (X6 = X4 + X5, записано как слово, старшие биты обнулены)
- R0 = 00000023 (уменьшился на 2)

---

## КОМАНДА 4: Адрес B2

**Код:** `97 91`  
**Мнемоника:** `DECB @(R1)+`  
**Комментарий:** X3 = X3 - 1

### Что делает команда:

DECB = Decrement Byte (декремент байта)

### Разбор по байтам:

- **97** = код операции DECB
- **91** = операнд: @(R1)+ (способ адресации 9 - косвенная через память с автоувеличением)
  - R1 содержит адрес ПЯ3 = 40C
  - @(R1)+ означает:
    1. Взять адрес из R1 (40C)
    2. Из ячейки 40C взять адрес операнда (19 - адрес X3)
    3. Взять значение из X3 (25)
    4. Уменьшить на 1: 25 - 1 = 24
    5. Записать результат обратно в X3 (19)
    6. Увеличить R1 на 4 → R1 = 410

### Что происходит:

1. Берется адрес X3 из ПЯ3 (19)
2. Берется значение X3 (25)
3. Уменьшается на 1: 25 - 1 = 24
4. Результат записывается в X3
5. R1 увеличивается до 410

### Результат:

- X3 (адрес 19) = 24
- R1 = 410

---

## КОМАНДА 5: Адрес B4

**Код:** `78 77 69 69`  
**Мнемоника:** `ASHL (R9)+ (R9)+ -(R7)`  
**Комментарий:** X8 = X8 \* 2^X9'

### Что делает команда:

ASHL = Arithmetic Shift Left (арифметический сдвиг влево)

### Разбор по байтам:

- **78** = код операции ASHL
- **77** = операнд 1 (счетчик сдвига): -(R7) (способ адресации 8)
  - R7 = 00000042 (начальное значение - адрес X9)
  - -(R7) означает:
    1. Уменьшить R7 на 4 → R7 = 3E
    2. Взять адрес из R7 (42)
    3. Взять значение из X9 (05 - младший байт)
    4. Это счетчик сдвига (X9' = X9 % 10 = 5)
- **69** = операнд 2 (значение для сдвига): (R9)+ (способ адресации 7)
  - R9 = 0000003B (после команды 2)
  - НО! R9 должен указывать на X8 (37)
  - (R9)+ означает:
    1. Взять адрес из R9 (37 - если R9 указывает на X8)
    2. Взять значение из X8 (001C980F)
    3. Увеличить R9 на 4 → R9 = 3F
- **69** = операнд 3 (результат): (R9)+ (способ адресации 7)
  - Результат записывается по адресу из R9
  - **ПРОБЛЕМА:** В мнемонике указано два раза (R9)+, но это может быть ошибка
  - На самом деле результат должен записываться в X8

### Что происходит пошагово (предположительно):

1. **Чтение счетчика:** R7 уменьшается до 3E, из X9 (адрес 42) берется значение 05
2. **Чтение X8:** Из адреса в R9 (37) читаем X8 = 001C980F
3. **Сдвиг влево:** 001C980F << 5 = 039301E0 (умножение на 2^5 = 32)
4. **Запись результата:** 039301E0 записывается в X8 (адрес 37)
5. **Обновление регистров:** R7 = 3E, R9 = 3F

### Результат:

- X8 (адрес 37) = 039301E0
- R7 = 0000003E (уменьшился на 4)
- R9 = 0000003F (увеличился на 4)

### Примечание:

Команда ASHL имеет формат: ASHL счетчик, значение, результат

- Счетчик: количество бит для сдвига (X9' = 5)
- Значение: что сдвигать (X8 = 001C980F)
- Результат: куда записать (X8 = адрес 37)

## КОМАНДА 6: Адрес B8

**Код:** `D8 96 69`  
**Мнемоника:** `ADWC` (Add With Carry)  
**Комментарий:** X7 = X7 + X8 + C

### Что делает команда:

ADWC = Add With Carry (сложение с переносом)

### Разбор по байтам:

- **D8** = код операции ADWC
- **96** = операнд 1: @(R6)+ (способ адресации 9)
  - R6 содержит адрес ПЯ2 = 406
  - @(R6)+ означает:
    1. Взять адрес из R6 (406)
    2. Из ячейки 406 взять адрес операнда (2D - адрес X7)
    3. Взять значение из X7 (00393100)
    4. Увеличить R6 на 4 → R6 = 40A
- **69** = операнд 2 (второе слагаемое и результат): (R9)+ (способ адресации 7)
  - R9 = 0000003F (после команды 5, но должен указывать на X8 = 37)
  - (R9)+ означает:
    1. Взять адрес из R9 (37 - если R9 указывает на X8)
    2. Взять значение из X8 (039301E0)
    3. Выполнить сложение: 00393100 + 039301E0 + C
    4. Записать результат обратно в X7 (через адрес из ПЯ2)
    5. Увеличить R9 на 4 → R9 = 3B

### Что происходит:

1. Берется X7 из памяти (00393100)
2. Берется X8 из памяти (039301E0)
3. Берется флаг переноса C
4. Выполняется сложение: X7 + X8 + C = 00393100 + 039301E0 + C = 03CC32E0
5. Результат записывается в X7

### Результат:

- X7 (адрес 2D) = 03CC32E0 (или 03CC32E1, в зависимости от флага переноса C)
- R6 = 0000040A (увеличился на 4)
- R9 = 0000003B (увеличился на 4)

## Объяснение способов адресации:

### Способ 6: Прямая регистровая (R)

- Код: 50 + номер регистра
- Пример: R3 = 53, R2 = 52, RC (R12) = 5C
- Значение берется напрямую из регистра

### Способ 7: Косвенная с автоувеличением ((R)+)

- Код: 60 + номер регистра
- Пример: (R9)+ = 69
- Процесс:
  1. Берется адрес из регистра
  2. По этому адресу берется значение
  3. Регистр увеличивается на размер операнда

### Способ 8: Косвенная с автоуменьшением (-(R))

- Код: 70 + номер регистра
- Пример: -(R0) = 70, -(R7) = 77
- Процесс:
  1. Регистр уменьшается на размер операнда
  2. Берется адрес из регистра
  3. По этому адресу берется значение

### Способ 9: Косвенная через память с автоувеличением (@(R)+)

- Код: 90 + номер регистра
- Пример: @(R8)+ = 98, @(R1)+ = 91, @(R6)+ = 96
- Процесс:
  1. Берется адрес из регистра (адрес ПЯ)
  2. Из ПЯ берется адрес операнда
  3. По адресу операнда берется значение
  4. Регистр увеличивается на размер длинного слова (4)

---

## Кодировка операндов VAX-11:

Для регистров R0-R15:

- R0 = 50, R1 = 51, R2 = 52, R3 = 53, ..., R9 = 59
- RA (R10) = 5A, RB (R11) = 5B, RC (R12) = 5C, RD (R13) = 5D, RE (R14) = 5E, RF (R15) = 5F

Для способов адресации:

- Способ 6 (R): 50 + номер регистра
- Способ 7 ((R)+): 60 + номер регистра
- Способ 8 (-(R)): 70 + номер регистра
- Способ 9 (@(R)+): 90 + номер регистра

---

## Примеры кодировки:

1. **R3** (способ 6) = 50 + 3 = **53**
2. **(R9)+** (способ 7) = 60 + 9 = **69**
3. **-(R0)** (способ 8) = 70 + 0 = **70**
4. **@(R8)+** (способ 9) = 90 + 8 = **98**

---

## Порядок выполнения команды:

1. Выбирается код операции
2. Вычисляется адрес первого операнда (со всеми изменениями регистров)
3. Выбирается первый операнд
4. Вычисляется адрес второго операнда
5. Выбирается второй операнд
6. Выполняется операция
7. Результат записывается

---

Это объясняет, почему регистры изменяются в определенном порядке и как работает косвенная адресация.

## Объяснение структуры программы

### Почему используются промежуточные ячейки (ПЯ)?

Промежуточные ячейки (ПЯ) используются для хранения адресов операндов, которые находятся в памяти. Это позволяет использовать косвенную адресацию через память (способ 9).

**Расположение ПЯ:**

- ПЯ1 (адрес 402): содержит адрес X1 = 0000000F
- ПЯ2 (адрес 406): содержит адрес X7 = 0000002D
- ПЯ3 (адрес 40C): содержит адрес X3 = 00000019

**Почему это нужно:**

- Команды с способом адресации 9 (@(R)+) требуют, чтобы в регистре был адрес ПЯ
- Из ПЯ берется адрес операнда
- Это позволяет работать с операндами в памяти через регистры

### Начальные значения регистров:

- **R0 = 00000025** - будет уменьшен до 23 для доступа к X4
- **R1 = 0000040C** - адрес ПЯ3 (содержит адрес X3)
- **R2 = 00000559** - значение X5 (слово)
- **R3 = 0000001C** - значение X2 (байт)
- **R6 = 00000406** - адрес ПЯ2 (содержит адрес X7)
- **R7 = 00000042** - адрес X9
- **R8 = 00000402** - адрес ПЯ1 (содержит адрес X1)
- **R9 = 00000037** - адрес X8
- **RC = 00002341** - значение X6 (слово)

### Почему регистры изменяются?

Регистры изменяются из-за способов адресации с автоувеличением (+) и автоуменьшением (-):

1. **Автоувеличение (+):** Регистр увеличивается ПОСЛЕ использования

   - Используется для последовательного доступа к данным
   - Размер увеличения зависит от размера операнда (байт=1, слово=2, длинное слово=4)

2. **Автоуменьшение (-):** Регистр уменьшается ДО использования
   - Используется для обратного доступа к данным
   - Размер уменьшения зависит от размера операнда

### Связь с алгоритмом:

**Алгоритм 7 (из рабочего файла):**

1. X1 = -X2 → Команда 1: MNEGB
2. X8 = X8 + X7 → Команда 2: ADDL2
3. X6 = X5 + X4 → Команда 3: ADDW3
4. X3 = X3 - 1 → Команда 4: DECB
5. X8 = X8 \* 2^X9' → Команда 5: ASHL
6. X7 = X7 + X8 + C → Команда 6: ADWC

**Почему именно такие команды:**

- MNEGB - для отрицания байта (X1 = -X2)
- ADDL2 - для сложения длинных слов (X8 = X8 + X7)
- ADDW3 - для сложения слов с записью в регистр (X6 = X5 + X4)
- DECB - для декремента байта (X3 = X3 - 1)
- ASHL - для сдвига влево (умножение на 2^n) (X8 = X8 \* 2^X9')
- ADWC - для сложения с переносом (X7 = X7 + X8 + C)

### Порядок выполнения команд:

1. **Команда 1 (A8):** X1 = -X2

   - Использует R3 (X2) и ПЯ1 (адрес X1)
   - R8 увеличивается до 406

2. **Команда 2 (AB):** X8 = X8 + X7

   - Использует ПЯ2 (адрес X7) и R9 (адрес X8)
   - R8 увеличивается до 40A, R9 увеличивается до 3B

3. **Команда 3 (AE):** X6 = X5 + X4

   - Использует R0 (адрес X4, уменьшается до 23), R2 (X5), RC (X6)
   - R0 уменьшается до 23

4. **Команда 4 (B2):** X3 = X3 - 1

   - Использует ПЯ3 (адрес X3)
   - R1 увеличивается до 410

5. **Команда 5 (B4):** X8 = X8 \* 2^X9'

   - Использует R7 (адрес X9, уменьшается до 3E), R9 (адрес X8)
   - R7 уменьшается до 3E, R9 увеличивается до 3F

6. **Команда 6 (B8):** X7 = X7 + X8 + C
   - Использует ПЯ2 (адрес X7) и R9 (адрес X8)
   - R6 увеличивается до 40A, R9 увеличивается до 3B

### Почему команды расположены именно так?

Команды расположены последовательно в памяти, начиная с адреса A8:

- A8: Команда 1 (3 байта: 8E 53 98)
- AB: Команда 2 (3 байта: C0 98 69)
- AE: Команда 3 (4 байта: A1 70 52 5C)
- B2: Команда 4 (2 байта: 97 91)
- B4: Команда 5 (4 байта: 78 77 69 69)
- B8: Команда 6 (3 байта: D8 96 69)

Адрес начала программы (A8) вычисляется по формуле: `nv*20 + ngl*100 = 168 = A8 (hex)`

---

## Итоговое понимание:

1. **Каждая команда** выполняет одну операцию алгоритма
2. **Способы адресации** определяют, как получить операнды
3. **Регистры** используются как указатели на адреса или хранят значения
4. **Промежуточные ячейки** хранят адреса операндов в памяти
5. **Автоувеличение/уменьшение** регистров происходит автоматически при использовании соответствующих способов адресации
6. **Результаты** записываются обратно в память или регистры согласно алгоритму

Это полное объяснение того, как работает программа и почему она написана именно так!
