## 2. Задание

### 2.1. Номер варианта

Параметры варианта:

- NV = 1 (номер по журналу)
- NGL = 1
- NGP = 2

### 2.2. Определение номера алгоритма

Формула: (NGP + NGL + NV) % 9

Расчет: (2 + 1 + 1) % 9 = 4 % 9 = 4

Алгоритм: Алгоритм 4

### 2.3. Описание действий алгоритма

Алгоритм 4 включает следующие операции:

1. X3 = X1 + X2 (сложение байтов)

   - Выполняет арифметическое сложение двух байтов
   - Результат записывается в X3

2. X9 = !X9 (побитовая инверсия байта)

   - Выполняет побитовую инверсию (NOT) байта X9
   - Каждый бит инвертируется: 0 → 1, 1 → 0
   - Результат записывается обратно в X9

3. X6 = X6 - 1 (декремент слова)
   - Вычитает единицу из значения слова X6
   - Результат записывается обратно в X6

## 3. Ход работы

### 3.1. Перевод исходных данных в шестнадцатеричную систему счисления

#### 3.1.1. Расчет исходных значений

Значения исходных данных определяются следующими формулами:

$$
\begin{array}{l}
X1 = (-1)^{NV} \cdot [(NV + NGP) \cdot 3] \\
X2 = (-1)^{(NV + 1)} \cdot [(NV + NGL) \cdot 2] \\
X3 = (-1)^{(NV + NGL)} \cdot [NV + NGP + NGL + 21] \\
X6 = (-1)^{(NV + NGL)} \cdot [NV + NGP + NGL + 79]^2 \\
X9 = (-1)^{(NV + NGL)} \cdot X6^2
\end{array}
$$

Подстановка значений NV = 1, NGL = 1, NGP = 2:

- X1 = (-1)^1 · [(1 + 2) · 3] = -1 · 9 = -9 (dec)
- X2 = (-1)^2 · [(1 + 1) · 2] = 1 · 4 = 4 (dec)
- X3 = (-1)^2 · [1 + 2 + 1 + 21] = 1 · 25 = 25 (dec)
- X6 = (-1)^2 · [1 + 2 + 1 + 79]^2 = 1 · 83^2 = 6889 (dec)
- X9 = (-1)^2 · 6889^2 = 1 · 47458321 = 47458321 (dec)

#### 3.1.2. Перевод в шестнадцатеричную систему и определение форматов

Определение минимального формата представления:

- Байт (byte): диапазон от -128 до 127 (8 бит)
- Слово (word): диапазон от -32768 до 32767 (16 бит)
- Длинное слово (longword): диапазон от -2 147 483 648 до 2 147 483 647 (32 бита)

Перевод и определение форматов:

| Переменная | Десятичное значение | Шестнадцатеричное значение | Минимальный формат | Примечание                    |
| ---------- | ------------------- | -------------------------- | ------------------ | ----------------------------- |
| X1         | -9                  | F7                         | Байт               | В диапазоне [-128, 127]       |
| X2         | 4                   | 04                         | Байт               | В диапазоне [-128, 127]       |
| X3         | 25                  | 19                         | Байт               | В диапазоне [-128, 127]       |
| X6         | 6889                | 1AE9                       | Слово              | В диапазоне [-32768, 32767]   |
| X9         | 47458321            | 02D3A311                   | Длинное слово      | Используется младший байт: 11 |

Примечание: X9 в программе используется как байт, поэтому берется только младший байт числа 02D3A311, то есть 11 (hex) = 17 (dec).

#### 3.1.3. Ожидаемые результаты операций

После выполнения операций:

- X3 = X1 + X2 = -9 + 4 = -5 (dec) = FB (hex)
- X9 = !X9 = !11 = EE (hex) = -18 (dec)
- X6 = X6 - 1 = 6889 - 1 = 6888 (dec) = 1AE8 (hex)

### 3.2. Первое действие: X3 = X1 + X2 (сложение)

#### 3.2.1. Размещение данных в памяти и регистрах

В регистрах (РОН):

- X2: R3 = 00000004 (байт, значение 04)

В памяти:

- X1: адрес 0F, значение F7 (байт)
- X3: адрес 19, значение 19 (байт, начальное значение) → после операции должно стать FB

Промежуточные ячейки (ПЯ):

**Примечание:** Адрес начала ПЯ по формуле: NV·NGP·1000 = 1·2·1000 = 2000 = 7D0 (hex). Однако в программе используется адрес 400 (1024 в десятичной системе), так как это стандартный адрес для размещения промежуточных ячеек в симуляторе VAX-11. Адрес 400 удобен для работы и не конфликтует с данными и командами, которые размещаются в начале памяти (адреса 0-200). Поэтому вместо расчетного адреса 7D0 используется адрес 400, а промежуточные ячейки размещаются начиная с адреса 402.

- ПЯ1 (адрес 402): 0000000F (адрес X1)
- ПЯ2 (адрес 406): 00000019 (адрес X3)

Регистры общего назначения:

- R3: 00000004 (значение X2)
- R8: 00000402 (адрес ПЯ1)
- R1: 00000406 (адрес ПЯ2)

#### 3.2.2. Определение способов адресации

**Что такое определение способов адресации:**

Определение способов адресации - это процесс выбора метода доступа к операндам команды. В VAX-11 существует множество способов адресации (прямая регистровая, косвенная через память, с автоувеличением и т.д.). Для каждого варианта задания определяется комбинация способов адресации по формуле: NV % 20, где NV - номер варианта. Это позволяет использовать разные способы адресации для разных вариантов, что обеспечивает разнообразие заданий.

**Вариант комбинации адресации:** NV % 20 = 1 % 20 = 1

Для операции X3 = X1 + X2 используется команда ADDB3 (Add Byte 3 операнда).

**Способы адресации:**

- Операнд 1 (X1): способ 9 - косвенная адресация через память с автоувеличением @(R8)+
- Операнд 2 (X2): способ 6 - прямая регистровая адресация R3
- Операнд 3 (результат в X3): способ 9 - косвенная адресация через память с автоувеличением @(R1)+

**Что такое косвенная адресация:**

Косвенная адресация - это способ адресации, при котором регистр содержит не само значение операнда, а адрес ячейки памяти, где хранится адрес операнда. В данном случае используется косвенная адресация через память с автоувеличением (способ 9): регистр указывает на промежуточную ячейку (ПЯ), которая содержит адрес операнда. После чтения адреса регистр автоматически увеличивается на размер длинного слова (4 байта).

**Что такое автоувеличение:**

Автоувеличение - это автоматическое увеличение значения регистра после использования адреса, на который он указывает. При использовании способа адресации @(Rn)+ регистр Rn сначала используется для получения адреса, а затем автоматически увеличивается на размер операнда (для длинного слова - на 4 байта). Это позволяет последовательно обрабатывать данные, расположенные в памяти друг за другом.

#### 3.2.3. Составление команды

**Как составляется мнемоника:**

Мнемоника (мнемонический код) - это символическое представление команды на языке ассемблера. Мнемоника составляется следующим образом: сначала указывается код операции (например, ADDB3 - Add Byte 3 операнда), затем через пробелы перечисляются операнды в порядке их использования. Каждый операнд записывается в виде, соответствующем способу адресации: R3 - прямая регистровая адресация, @(R8)+ - косвенная адресация через память с автоувеличением. Мнемоника читается слева направо: код операции, затем операнд 1, операнд 2, операнд 3.

**Мнемоника:** `ADDB3 @(R8)+ R3 @(R1)+`  
**Комментарий:** X3 = X1 + X2

Разбор команды:

- ADDB3 - код операции 81 (Add Byte 3 операнда)
- @(R8)+ - операнд 1 (X1): код 98 (способ 9, регистр R8)
  - R8 = 00000402 (адрес ПЯ1)
  - Из ПЯ1 читается адрес X1 (0F)
  - Берется значение X1 = F7
  - R8 увеличивается на 4 → R8 = 00000406
- R3 - операнд 2 (X2): код 53 (способ 6, регистр R3)
  - R3 = 00000004 (значение X2)
  - Берется младший байт: 04
- @(R1)+ - операнд 3 (результат в X3): код 91 (способ 9, регистр R1)
  - R1 = 00000406 (адрес ПЯ2)
  - Из ПЯ2 читается адрес X3 (19)
  - Выполняется сложение: F7 + 04 = FB
  - Результат записывается в X3 (адрес 19) = FB
  - R1 увеличивается на 4 → R1 = 0000040A

Машинный код: `81 98 53 91`

Адрес команды: NV·20 + NGL·100 = 1·20 + 1·100 = 120 = 78 (hex)

#### 3.2.4. Трассировка команды

До выполнения:

- X1 (адрес 0F) = F7 (hex) = -9 (dec)
- X2 (R3) = 04 (hex) = 4 (dec)
- X3 (адрес 19) = 19 (hex) = 25 (dec)
- R8 = 00000402
- R1 = 00000406

После выполнения:

- X1 (адрес 0F) = F7 (hex) = -9 (dec) ✓ (не изменилось)
- X2 (R3) = 04 (hex) = 4 (dec) ✓ (не изменилось)
- X3 (адрес 19) = FB (hex) = -5 (dec) ✅
- R8 = 00000406 (увеличилось на 4)
- R1 = 0000040A (увеличилось на 4)

Проверка: F7 + 04 = FB ✓

### 3.3. Второе действие: X9 = !X9 (побитовая инверсия)

#### 3.3.1. Размещение данных в памяти и регистрах

В памяти:

- X9: адрес 41, значение 11 (байт, начальное значение) → после операции должно стать EE

Промежуточные ячейки (ПЯ):

- ПЯ4 (адрес 410): 00000041 (адрес X9, источник)
- ПЯ5 (адрес 414): 00000041 (адрес X9, приемник)

Регистры общего назначения:

- R9: 00000410 (адрес ПЯ4)
- R6: 00000414 (адрес ПЯ5)

Примечание: После выполнения команды 1:

- R1 = 0000040A
- R8 = 00000406

#### 3.3.2. Определение способов адресации

Вариант комбинации адресации: NV % 20 = 1 % 20 = 1

Для операции X9 = !X9 используется команда MCOMB (Move Complement Byte).

Способы адресации:

- Операнд 1 (источник X9): способ 9 - косвенная адресация через память с автоувеличением @(R9)+
- Операнд 2 (приемник X9): способ 9 - косвенная адресация через память с автоувеличением @(R6)+

**Что такое однооперандная и двухоперандная команда:**

Однооперандная команда - это команда, которая работает с одним операндом (например, DECW @(R5)+, где операнд один - X6). Двухоперандная команда - это команда, которая работает с двумя операндами: источником (откуда берется значение) и приемником (куда записывается результат). Например, MCOMB @(R9)+ @(R6)+ - двухоперандная команда, где первый операнд @(R9)+ является источником (откуда читается значение X9), а второй операнд @(R6)+ является приемником (куда записывается результат инверсии). Источник - это операнд, из которого берется исходное значение для операции. Приемник - это операнд, в который записывается результат операции.

**Примечание:** MCOMB - двухоперандная команда: оп2 = !оп1. Требует две промежуточные ячейки для одного операнда, так как один и тот же операнд X9 используется и как источник, и как приемник.

#### 3.3.3. Составление команды

Мнемоника: `MCOMB @(R9)+ @(R6)+`  
Комментарий: X9 = !X9

Разбор команды:

- MCOMB - код операции 92 (Move Complement Byte)
- @(R9)+ - операнд 1 (источник X9): код 99 (способ 9, регистр R9)
  - R9 = 00000410 (адрес ПЯ4)
  - Из ПЯ4 читается адрес X9 (41)
  - Берется значение X9 = 11
  - R9 увеличивается на 4 → R9 = 00000414
- @(R6)+ - операнд 2 (приемник X9): код 96 (способ 9, регистр R6)
  - R6 = 00000414 (адрес ПЯ5)
  - Из ПЯ5 читается адрес X9 (41)
  - Выполняется побитовая инверсия: !11 = EE
  - Результат записывается в X9 (адрес 41) = EE
  - R6 увеличивается на 4 → R6 = 00000418

Машинный код: `92 99 96`

Адрес команды: Следующий после команды 1: 78 + 4 = 7C, но там HALT, поэтому 7D (hex)

#### 3.3.4. Трассировка команды

До выполнения:

- X9 (адрес 41) = 11 (hex) = 00010001 (bin) = 17 (dec)
- R9 = 00000410
- R6 = 00000414

После выполнения:

- X9 (адрес 41) = EE (hex) = 11101110 (bin) = -18 (dec) ✅
- R9 = 00000414 (увеличилось на 4)
- R6 = 00000418 (увеличилось на 4)

Проверка:

```
11 (hex) = 0001 0001 (bin)
!11      = 1110 1110 (bin) = EE (hex) ✓
```

### 3.4. Третье действие: X6 = X6 - 1 (декремент)

#### 3.4.1. Размещение данных в памяти и регистрах

В памяти:

- X6: адрес 23, значение 1AE9 (слово, 16 бит) → после операции должно стать 1AE8
  - В формате little-endian: E9 1A (младший байт E9 по адресу 23, старший байт 1A по адресу 24)

**Что такое формат little-endian:**

Little-endian (младший байт вперед) - это порядок байтов, при котором младший (наименее значимый) байт многобайтового числа хранится по младшему адресу памяти. Например, слово 1AE9 (hex) в формате little-endian хранится как два байта: E9 (младший байт) по адресу 23 и 1A (старший байт) по адресу 24. Это стандартный формат для процессоров VAX-11 и x86. В противоположность big-endian, где старший байт хранится первым.

Промежуточные ячейки (ПЯ):

- ПЯ6 (адрес 418): 00000023 (адрес X6)

Регистры общего назначения:

- R5: 00000418 (адрес ПЯ6)

Примечание: После выполнения команды 2:

- R6 = 00000418
- R9 = 00000414

#### 3.4.2. Определение способов адресации

Вариант комбинации адресации: NV % 20 = 1 % 20 = 1

Для операции X6 = X6 - 1 используется команда DECW (Decrement Word).

Способы адресации:

- Операнд (X6): способ 9 - косвенная адресация через память с автоувеличением @(R5)+

Примечание: Используется R5 вместо R7, чтобы избежать конфликта кодов (DECB = 97, @(R7)+ может быть 97).

#### 3.4.3. Составление команды

Мнемоника: `DECW @(R5)+`  
Комментарий: X6 = X6 - 1

Разбор команды:

- DECW - код операции B7 (Decrement Word)
- @(R5)+ - операнд (X6): код 95 (способ 9, регистр R5)
  - R5 = 00000418 (адрес ПЯ6)
  - Из ПЯ6 читается адрес X6 (23)
  - Берется слово из X6 = 1AE9
  - Выполняется декремент: 1AE9 - 1 = 1AE8
  - Результат записывается в X6 (адрес 23) = 1AE8
  - R5 увеличивается на 4 → R5 = 0000041C

Машинный код: `B7 95`

Адрес команды: Следующий после команды 2: 7D + 3 = 80, но там HALT, поэтому 81 (hex)

#### 3.4.4. Трассировка команды

До выполнения:

- X6 (адрес 23-24) = E9 1A (little-endian) = 1AE9 (hex) = 6889 (dec)
- R5 = 00000418

После выполнения:

- X6 (адрес 23-24) = E8 1A (little-endian) = 1AE8 (hex) = 6888 (dec) ✅
- R5 = 0000041C (увеличилось на 4)

Проверка:

```
X6 (до)  = 1AE9 (hex) = 6889 (dec)
X6 (после) = 1AE8 (hex) = 6888 (dec) ✓
```

## 4. Выводы по лабораторной работе

В ходе выполнения данной лабораторной работы были получены и закреплены навыки работы с ассемблером для процессоров семейства VAX, а в частности работы с процессором VAX-11. Изучены форматы команд и способы адресации процессора VAX-11, включая прямую регистровую адресацию (способ 6), которая использовалась для операнда X2 в регистре R3, и косвенную адресацию через память с автоувеличением (способ 9), которая применялась для операндов в памяти через промежуточные ячейки. Освоены различные способы косвенной адресации операндов, включая использование промежуточных ячеек (ПЯ) для хранения адресов операндов, автоматическое изменение регистров при использовании способов адресации с автоувеличением, а также косвенная адресация через память для работы с операндами в памяти. Составлена программа для выполнения алгоритма арифметико-логической обработки данных с реализацией операций сложения байтов (ADDB3) для операции X3 = X1 + X2, побитовой инверсии байта (MCOMB) для операции X9 = !X9, и декремента слова (DECW) для операции X6 = X6 - 1. Программа протестирована путем ручной трассировки, при этом все результаты выполнения команд совпали с ожидаемыми: X3 = FB (результат сложения F7 + 04), X9 = EE (результат инверсии 11), X6 = 1AE8 (результат декремента 1AE9 - 1). Изменения регистров и памяти отслежены на каждом шаге выполнения программы, при этом все регистры (R1, R5, R6, R8, R9) корректно увеличивались на 4 при использовании способа адресации с автоувеличением.

Изучено представление данных в формате little-endian, где байты хранятся как есть, слова хранятся с младшим байтом первым (например, 1AE9 хранится как E9 1A), а длинные слова занимают 4 байта в памяти. Понята структура команд VAX-11, где код операции определяет тип команды и формат данных, операнды кодируются байтами в зависимости от способа адресации, а размер команды зависит от количества и типов операндов. Работа была выполнена с использованием эмулятора VAX-11 и запускалась на нем. Были закреплены навыки изучения технической документации, получены навыки работы с различными способами адресации и форматами данных процессора VAX-11, что позволило успешно реализовать все три операции алгоритма и проверить корректность их выполнения путем сравнения результатов ручной трассировки с результатами работы программы в эмуляторе.
