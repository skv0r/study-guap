# ДИАГНОСТИКА И РЕШЕНИЕ

## Проблема сохраняется

Даже с косвенной адресацией результат записывается в 006B вместо 006C.

## СРОЧНО ПРОВЕРЬТЕ:

### 1. Что записано в ПЯ3?

Откройте память по адресу **04D7** и проверьте:
- Должно быть: **6C 00 00 00** (адрес 006C)
- Если там что-то другое - вот проблема!

### 2. Что в R2?

Проверьте значение R2:
- Должно быть: **R2 = 000004D7** (адрес ПЯ3)
- Если там что-то другое - исправьте!

### 3. Что записано в программе?

Проверьте память по адресам 03C0-03C4:
- 03C0 должно быть: **C0**
- 03C1 должно быть: **90**
- 03C2 должно быть: **91**
- 03C3 должно быть: **92**

---

## НОВОЕ РЕШЕНИЕ: Используем регистр для результата

Если косвенная адресация не работает, попробуем записать результат в регистр, а потом переместить его.

### Вариант 1: ADDB2 + MOVB

**Шаг 1: Установите регистры**

```
R0 = 000004CF
R1 = 000004D3
R5 = 00000000    (для хранения результата)
R6 = 0000006C    (адрес X3)
```

**Шаг 2: Программа**

```
Адрес 03C0: 80    (ADDB2 - сложение 2 операндов)
Адрес 03C1: 90    (@(R0)+ - первый операнд X1)
Адрес 03C2: 55    ((R5) - результат в регистр R5)

Адрес 03C3: 90    (ADDB2 - добавить второй операнд)
Адрес 03C4: 91    (@(R1)+ - второй операнд X2)
Адрес 03C5: 55    ((R5) - добавить к результату в R5)

Адрес 03C6: 94    (MOVB - переместить байт)
Адрес 03C7: 55    (источник (R5))
Адрес 03C8: 56    (назначение (R6) - адрес X3)
```

Это сложно, но может сработать.

## Вариант 2: Проверка формата команды

Может быть проблема в том, что ADDB3 в вашем приложении работает не так?

Попробуйте использовать **ADDB2** (2 операнда) дважды:

**Шаг 1: Установите**

```
R0 = 000004CF
R1 = 000004D3
R2 = 0000006C
```

**Шаг 2: Программа**

```
Адрес 03C0: 80    (ADDB2)
Адрес 03C1: 90    (@(R0)+ - X1)
Адрес 03C2: 52    ((R2) - результат в X3, но это добавит X1 к X3)

Адрес 03C3: 80    (ADDB2)
Адрес 03C4: 91    (@(R1)+ - X2)
Адрес 03C5: 52    ((R2) - добавить X2 к X3)
```

Но это тоже не то, что нужно...
